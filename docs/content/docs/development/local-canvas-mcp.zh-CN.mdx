# 本地画布 MCP 连接原理

画布 MCP 已经融合进前端本身：运行前端时（`npm run dev`，或 `npm run start` 预览生产构建），同一个 Vite 服务在 `http://127.0.0.1:3000` 上同时提供浏览器桥接和 `/mcp` 的 Streamable HTTP MCP 端点，不需要再单独启动任何包或进程。

```text
MCP 客户端（opencode 等）        浏览器画布
              \                    /
        前端服务（HTTP + SSE，端口 3000）
```

## 浏览器桥接

画布页面在同源下自动连接，无需 token、无需手动连接：

```text
GET  /events?clientId=xxx        （SSE）
POST /canvas/state?clientId=xxx
POST /canvas/activate?clientId=xxx
POST /canvas/result?clientId=xxx
```

快照包含画布 ID 与标题、节点、连线、选中节点 ID 和视口。服务端在内存中保存最新快照，因此读取类工具返回的是结构化状态，而不是 DOM。

执行节点创建时，MCP 客户端调用工具，服务端把它转换成 `canvas_apply_ops`，通过 SSE 发送 `tool_call`，浏览器应用 `add_node`、`update_node`、`delete_node`、`delete_connections`、`connect_nodes`、`set_viewport`、`select_nodes`、`run_generation`、`arrange_board`、`place_on_board` 等操作，再把结果 POST 回 `/canvas/result`，完成这次 MCP 调用。

## HTTP MCP

MCP 客户端连接同一个端口上的 Streamable HTTP 端点：

```text
POST http://127.0.0.1:3000/mcp
```

服务端为每个已初始化的会话创建一个 `McpServer`，后续请求按 `mcp-session-id` 请求头路由。它对外声明 `opencanvas-mcp` 服务名并暴露 32 个画布工具：站点级工具转发给浏览器，画布读取类工具用最新快照直接回答，其余画布工具转换成 `canvas_apply_ops`。`canvas_create_node` 与 `canvas_apply_ops` 支持全部内置节点类型（文本、提示词、音乐提示词、语音提示词、图片、视频、音频、生成配置、图片生成、语音生成、音乐生成、智能画布、素材、录音、图片修饰）。

## 安全边界

- 服务挂载在前端自身的服务器上、共用同一个端口，不是独立监听。
- 桥接与 MCP 请求只接受同源或本机来源；没有 `Origin` 请求头的非浏览器 MCP 客户端放行。不再有 token 或配置文件。
- MCP 客户端不直接访问 DOM，也不持有画布状态。
- 线上站点不保存本地登录态、API Key 或本地文件权限。

简而言之：读取时，数据从浏览器快照经前端服务流到 MCP 客户端；写入时，指令从 MCP 客户端经 SSE 桥接回到浏览器 React 状态。
