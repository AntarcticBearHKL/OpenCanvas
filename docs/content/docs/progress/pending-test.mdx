# Pending Tests

The current release needs manual verification in these areas:

## VST3 instrument picker

- The piano roll's instrument picker (open an instrument track's MIDI region) now has a VST3 group beside the built-in presets, fed by the local host's `scan` (instruments only, listed as `name · vendor`). Picking one writes `{ kind: "vst3", pluginId, name }` onto that track through the normal track update, so it persists with the rest of the project.
- Start the host manually first: `vst-host\build\bin\vst-host.exe` with `VST_HOST_TOKEN` and `VST_HOST_ORIGINS` set (it listens on 127.0.0.1:3211). The picker reads the same runtime config / `canvas-vst-url` + `canvas-vst-token` overrides as the rest of the VST bridge.
- Manual test: start the host, open an instrument track's MIDI region (double-click the region), open the 「音色」 picker and choose a scanned VST3 instrument (e.g. Retrologue · Steinberg) — pressing Play or playing the piano-roll keys should sound through the plugin. Switching back to a built-in preset keeps working.
- Stop the host and reload: the picker shows 「本地 VST 宿主未运行」 next to it, lists only the built-in presets (plus the track's already-selected VST3 entry so it stays readable), and opening the roll never throws or hangs. Picking a different VST3 instrument is intentionally not possible while the host is down.
- There is now a 「打开插件界面」 action in the piano roll toolbar, right after the 「音色」 picker: it calls the host's `editorOpen` for that track's bridge instance, so the plugin's own native window opens on the desktop (the editor is an HWND owned by the host process and cannot be embedded in the page — this is what makes loading presets in HALion Sonic possible). The action only appears once the bridge is `ready` (an `instanceId` exists on `graph.vstSources`); while the attach is pending, offline or failed it shows a short Chinese state hint instead of a dead button, and an open failure (e.g. the host was stopped between ready and click) shows a non-fatal 「打开插件界面失败」 hint beside the button.
- Manual test: start the host (`vst-host\build\bin\vst-host.exe` with `VST_HOST_TOKEN` / `VST_HOST_ORIGINS`), open an instrument track's MIDI region, pick a scanned VST3 instrument (e.g. Retrologue · Steinberg), press Play once (this unlocks the audio context and builds the bridge) and wait until 「打开插件界面」 appears next to the picker; click it and the plugin's own window should appear on the desktop — in HALion Sonic you can now load presets — then close the plugin window and keep working. Stop the host and reload: the button is not offered, pressing Play makes the bridge attach fail and the roll shows 「插件加载失败」 instead, with no error thrown and no stuck state.
- **How to build / run the host** is documented in `vst-host/README.md`: it needs the VST3 SDK cloned locally (`git clone --depth 1 --recurse-submodules --shallow-submodules https://github.com/steinbergmedia/vst3sdk.git vst-host/external/vst3sdk`), then a CMake Visual Studio 2022 x64 Release build; the exe lands in `vst-host/build/bin/`. Stop it with `vst-host.exe --stop` (it also refuses to start — naming the holder's PID — when the port is already taken, and cleans up a stale PID file on its own).
- **Known limitation — export skips VST3 tracks.** Offline mixdown / stem export renders through `Tone.Offline`, which cannot run a real-time native plugin, so a VST3 instrument track is left out of the exported audio (the graph reports this explicitly instead of failing silently). Exports that must include the VST3 track have to wait for freeze / bounce-in-place. Worth confirming that exporting a project which contains a VST3 track still produces a valid file for the remaining tracks.

## Audio studio: track menu and media pool

- The audio studio menu bar no longer has a "Track" menu — only Edit / Clip / View / Automation remain. The five add-track entries (audio / instrument / MIDI / group / return) now live behind the "Add track" button, which opens a dropdown; both the row at the end of the lane list and the empty-state button were changed (they no longer add an audio track in one click).
- The track-level actions moved onto every track row: duplicate / remove / export stems are in a new "⋯" button (label "Track actions") at the right end of the track header. The same menu still opens on right-click. `Remove` stays disabled when only one non-master track remains, and `Export stems` stays disabled while an export is running. Note that "Export stems" exports the **whole project**, not the track whose "⋯" you clicked.
- The Media pool is now drag-only: the per-row "＋" and the "add to the selected track" click flow are gone. Drag a media-pool row onto any track lane to create a clip at the pointer's timeline position (snapped to the grid); the target lane highlights while a valid drop hovers it, and a non-audio drag or a lane that cannot host clips rejects the drop. The MIDI track's "add region" ＋ and the empty-state "go to canvas" ＋ are unchanged.

## MCP page namespaces

- The MCP service is now a generic page + action-namespace relay instead of canvas-only. Three generic tools drive any page through the list → describe → call flow: `app_get_state` (read the current page snapshot), `app_describe_actions` (fetch a namespace's JSON Schema) and `app_apply_ops` (apply a batch of namespaced ops). The protocol is now 7 and the tool count is 29 (3 generic + 3 site + 23 canvas shortcut macros); the four old tools (`canvas_get_state`, `canvas_get_selection`, `canvas_export_snapshot`, `canvas_apply_ops`) are gone, while `site_navigate`, `canvas_list_projects` and `generation_get_status` remain.
- Round-trip: connect an MCP client, call `app_get_state` and confirm `availableActions` lists the four namespaces (`canvas`, `image`, `audio`, `config`), call `app_describe_actions` for each and confirm its schema comes back, then submit one op per namespace through `app_apply_ops` and confirm the page applies it.
- `canvas` (49 ops): node layer / lock / hide / bulk rename / font size / free resize / resize / content / title / metadata / batch image / align, video slots, board ratio / resolution / background / layer order, and the async ops (crop / split / upscale / OCR / remove background / angle / retry / compose / save as node).
- `image` (36 ops): layers (add / remove / duplicate / group / ungroup / move / transform / patch / style / rasterize), the layer factories (pixel / text / shape / adjustment / image), document scale / offset / rotate / trim / anchor, board ratio / resolution / background, and filter / compose / export.
- `audio` (65 ops): tracks, clips, MIDI notes and regions, the mixer (gain / pan / mute / solo / sends), transport and session (tempo / time signature / grid / cycle / punch / metronome / count-in / capture / PPQN), markers, automation lanes and points, and mixdown / stem export.
- `config` (12 ops): confirm it is `danger: true` and deny-by-default, so every config op is blocked until an operator opts in; the published snapshot always redacts secrets to `{ hasKey, last4 }`; and `config.set_provider_key` and `config.reveal_key` stay false even when `config:*` is enabled. Raw keys transit the local MCP service, so the loopback / token / origin guards do not protect against a malicious MCP client.

## Providers, hardcoded models and Matilda

- Only three providers are offered now: OpenRouter, DeepSeek and Matilda (Maincode). Each channel's model list comes from its preset — OpenRouter carries the multimodal set (image `openai/gpt-image-2.5-sunburst`, video `minimax/hailuo-3-max` / `minimax/hailuo-3`, speech `fish-audio/s2.1-pro`, music `google/lyria-3-pro-preview`, plus five text ids), DeepSeek carries `deepseek-v4-pro` / `deepseek-v4-flash`.
- The "fetch models" action is gone: no `GET {base}/models` call and no per-provider fetch button. Removing it was the right call — the live OpenRouter catalogue (458 models) does not contain this app's image / video / speech ids at all, so fetching produced a list the app cannot use.
- DeepSeek and Matilda are text-only: their models are always classified `text`, the capability control is read-only for them, and they never appear in the image / video / audio / speech pickers. Channels for other providers are untouched; only preset-matching channels have their model list reset.
- Matilda runs through a local same-origin proxy (`web/matilda-proxy.ts`, registered in `vite.config.ts` for dev and preview). The proxy drives the official `@maincode-ai/matilda-agent-sdk` in Node and re-exposes Matilda as OpenAI-shaped `/matilda/v1/responses`, `/matilda/v1/chat/completions` and `/matilda/v1/models`, so you only paste an `mc_live_...` key into the Matilda channel — no model id, no capability choice.
- Things worth checking on your side: (a) the Matilda happy path has NOT been tested with a real key (none exists on this machine — the SSE translation was verified by replaying the SDK's real event names through a mock, and the live cloud was probed only down to its 401 path); (b) if a Matilda channel was already saved with the old absolute URL `https://matilda.maincode.com/api/v1`, re-select the "Matilda (Maincode)" preset once (or delete that channel); (c) `npm run dev` gets the proxy, but `npm run start` serves a stale `dist`, and a static production deploy would need an equivalent Node function for the proxy; (d) a Matilda request containing only images returns a clear 400 instead of a hallucinated answer.

## Canvas nodes and editing

- Node names are always shown above the card, with no per-node name toggle. The hover-toolbar "Show labels" switch controls the text labels of hover-toolbar buttons for every node type and keeps its state after a reload.
- Node cards have no default outline; only selection, related-node and drop-target states draw an outline.
- The node list and the hover toolbar can lock or hide nodes. A locked node cannot be dragged, resized, edited, deleted or picked up by range selection but stays selectable so it can be unlocked; a hidden node is not rendered and cannot be clicked or targeted by a connection but can be restored from the node list; one undo reverts each lock, hide or rename.
- The bottom-toolbar Node list button (and the hover-toolbar Layers popover) opens a panel that filters nodes by type, renames several selected rows in one action (a single row keeps its exact name, several get number suffixes) and toggles lock/hide per row.
- Dragging a node snaps it to a 16px canvas grid, but an alignment guide wins when an edge or centre comes within 6 screen pixels of another node; the released position matches the drag preview at every zoom level.
- Dragging only resource nodes (image / video / audio) shows a small fixed-size ghost card at the cursor (about 44px, the node's type icon plus its truncated title, and a ×N badge when several nodes are dragged) while the real dragged nodes fade to a quarter opacity, so the Assets node, the image-modifier node and the video prompt slots stay visible underneath; a plain click never flashes a ghost, and dragging any other node type (text, config, smart canvas, generation nodes) keeps the previous full-size drag with no fade. Node geometry, connection anchors, drop-target detection, snapping and the per-mousemove cost are unchanged.
- With two or more nodes selected, the selection toolbar shows six align actions (left, horizontal centre, right, top, vertical centre, bottom); with three or more it also shows horizontal and vertical distribute. Each action moves only the selected nodes, and one undo reverts the whole move.
- Every connection shows a short relationship label at its midpoint (Reference image / Reference video / Reference audio / Prompt / Composite, the derived operation such as Background removed / Cropped / Split / Upscaled / Enhanced / Mask edited / Video frame / Generation result, Group content, or a generic Linked fallback); clicking the label selects the connection and the label keeps a constant on-screen size while zooming.

- Image nodes render as WebP thumbnails whose longest side is 512px on the canvas, and the original is loaded only for the large preview; an older image lazily generates its thumbnail on first render.
- Right-clicking the blank canvas, a node or a connection shows the browser's native context menu, and holding Ctrl while right-dragging draws a stroke; every connection the stroke crosses is cut and one undo restores them.

A left tool column (Select V / Range R / Split C / Draw D / Erase E / Glue G / Hand H / Zoom Z, plus zoom in/out) and an options row carrying the Edit / Track / Clip / View / Automation menus, the grid toggle, the snap selector (off / bar / beat / 1/2 / 1/4 / 1/8 / 1/16, coarsened so a cell never gets sub-pixel), the fade shape, clip gain, loop and reverse toggles, auto-crossfade and the snap indicator, with dockable panels in the same system as the Image Studio: a right dock holding Inspector / Automation / History and a left dock holding Media pool / Markers / Project settings, every panel toggled from the options row's Window menu, moved between the left, right and bottom docks by dragging its tab and resized by dragging a dock's splitter. Every track lane keeps its editable name and adds record-arm, mute and solo (solo wins over mute, and any solo silences the other tracks) plus a fader shown in dB but stored linear; every clip carries a name, gain, fade in/out (rendered linear; exponential and S-curve are stored for a later stage), loop, reverse, mute, colour and lock, can be moved inside a lane or onto another lane, trimmed from either edge, faded from its top corners, loop-extended with Alt+drag on the right edge, split by the split tool, its context menu or Ctrl+K, duplicated with Alt+drag or Ctrl+D, copied / cut / pasted around the playhead, nudged by the grid or by a whole bar with Shift, deleted, muted, locked, renamed and colour-picked from its context menu or properties dialog, and overlapping clips on one lane receive complementary fades automatically unless auto-crossfade is off; a clip whose source node is gone degrades to a dashed note instead of failing, and every gesture writes once on pointer release so one drag is one undo step. Markers can be added from the ruler or the Markers panel (rename, seek, delete). All edits still go into the same node's metadata (clips only reference canvas audio nodes by id), so reload persistence, undo/redo and project export keep working. The second stage adds the mixer, routing and buses: an Arrangement / Mixer switch sits in the centre header, and the Mixer shows one Cubase-like strip per track — colour chip, sends (target, pre/post, gain, enable, remove), pan, a dB fader with a stereo meter, mute / solo / record-arm and an output selector — with the master strip pinned at the right end and its fader bound to the project master gain; tracks now have types (audio / group / return / master, a new project is seeded with one audio track plus a master), per-track output routing that refuses cycles, aux sends that only target return tracks, and global solo/mute resolved over the routing graph (soloing a group pulls its children in, a muted bus silences everything routed through it, solo still wins over a track's own mute); the right dock's Inspector tab edits the selected track (name, colour, type, gain, pan, M / S / arm, output, sends) and summarises the selected clip, the Media pool tab lists the canvas's audio nodes and adds them to the selected track (or points you back to the canvas when there are none), and the Project settings section now holds tempo, meter, grid, cycle in/out, punch in/out, metronome and master gain, with the punch range drawn on the ruler. Playback and the offline export both render through one shared graph builder (per track: input → mute/solo gate → pre-fader send taps → fader → panner → post-fader send taps → output, then the master strip to the destination), so the exported WAV matches what you hear; Save as audio node still writes the result back onto the canvas as a new audio node. The third stage adds parameter automation: a track can own lanes for its volume, its pan and any of its send gains (one lane per parameter, several per track), each lane sharing the timeline's horizontal scale and drawing a 1 px polyline through 6 px breakpoints — double-click empty lane space adds a point, dragging moves it (Shift suspends snap and the value stays clamped between the neighbouring points), double-clicking a point deletes it and its right-click menu switches the interpolation between linear, hold and S-curve. The lane header carries the parameter selector (another parameter already taken by a lane is not offered) and an enable toggle; the track header gains a chevron that folds the track's lanes, the Automation menu stops being a placeholder and adds a volume / pan / send lane or clears the selected track's automation (a new lane also unfolds the track and focuses the dock tab), and the right dock's Automation tab stops being a placeholder and lists the selected track with one row per lane (target, point count, enable switch, clear points, remove) plus the gesture hints. An enabled lane with breakpoints owns its parameter: the shared graph builder schedules each breakpoint as an AudioParam event on the transport (hold is a step, S-curve is approximated by six linear ramps), rebuilds the schedule on transport start and on a cycle loop so a seek never leaves a stale ramp, and the offline mixdown renders through the same builder so the exported WAV carries the automation too; a fader that is automated shows a link icon and is read-only in the mixer strip, the inspector, the send slots and the lane's mini fader, so a manual move can never overwrite a lane, and deleting a track or a send prunes the automation lanes pointing at it. A drag is held as a draft and committed once on pointer release (one gesture = one undo step), and the lanes live in the audio project node's metadata like the rest of the document. The fourth stage is waveforms, scale, small screens and accessibility: every clip waveform is now a multi-resolution min/max peak pyramid (one bucket per 1024 samples, the band chosen by zoom, both the pyramid and the decoded PCM held in memory behind LRU caps so peaks and playback share a single download and decode per source) painted onto that clip's own canvas, and the canvas is clamped to the horizontally scrolled window so a long clip can neither make an oversized canvas nor paint off screen; the arrangement virtualizes its lanes, so only the lanes inside the vertical scroll window (plus a small overscan) are rendered and the rest keep their height. The audio graph is now built only after the first gesture unlocks the audio context, and the first Play waits for the graph so it is never silent; the document keys are split into a structural key (strips, players, send taps) and a mixer key (faders, pan, mute/solo, send gains, clip gain and fades, automation ramps), so moving a fader or editing an automation point no longer rebuilds the players — automation is re-scheduled on the live graph instead. Narrow widths follow the workspace's responsive rules: below 768px the right dock collapses into an overlay opened from a header button (it takes focus, closes on an outside click or Escape and keeps Tab inside), the tool column becomes a horizontal strip under the options row, the transport shrinks to back / play-pause / position plus a `…` menu (return to start, stop, record, cycle, metronome, zoom, export) and the options row collapses into a single Options dropdown holding the five DAW menus plus the contextual grid/snap/fade-shape/loop/reverse/auto-crossfade items, with the clip gain and fades still reachable from the clip properties dialog; the mixer shows one strip at a time behind a track selector instead of scrolling; keyboard users get a token-coloured focus-visible outline instead of the browser default, automation points are focusable and nudge-able with the arrow keys (Enter cycles linear / hold / S-curve, Delete removes one), and a focused clip opens the inspector with Enter (Enter anywhere else still returns to the start). Stage 1-3 behaviour, the shared graph builder and the mixdown path are unchanged.
- The fifth stage adds MIDI and instrument tracks: a track can now be an Instrument or MIDI track, each owning a built-in synth (an instrument track picks its timbre from a preset list). MIDI regions are stored in PPQN ticks (960 per quarter note) so they follow the project tempo, and can be moved, trimmed on either edge, split, duplicated and deleted in the arrangement like a clip. Double-clicking a region — or the new Piano roll view in the centre switcher — opens a basic piano-roll editor over that region's own pitch range: double-click empty space to draw a note, drag a note to move it, drag its right edge to resize, drag the velocity lane below to set velocity, double-click a note or press Delete to remove it, and arrow keys nudge the selection (Shift = bar / octave). The synth feeds the same channel strip as a clip source, so fader, pan, mute, solo, sends and output routing all apply, and playback and the offline mixdown still share the one audio graph builder, so the exported WAV contains the MIDI tracks too.
- The sixth stage adds recording and export hardening. The transport's record button (the circle left of the position readout, and in the narrow `…` menu) now records instead of only toggling record-arm: with an audio track armed, clicking it unlocks the audio context and opens the browser's default input inside that same gesture, plays the count-in chosen in the project settings (0 / 1 / 2 / 4 bars — the clicks run on the audio clock before the transport starts and accent every bar, so a lead-in never shifts the take) and starts the transport rolling from the playhead, with a punch take cut out of that capture so only its range is recorded; clicking it again, or pressing Space, Pause or Stop, ends the take, and a take also ends by itself at a punch out point or at the project end. The button shows the take (engaged `activeBg` with the blocked colour) instead of the arm state — arming stays on the lane header, the mixer strip and the inspector, and clicking record with nothing armed warns instead of silently doing nothing. The project settings gained a Recording input block next to punch and the metronome: record mode (Normal records from the playhead, Punch records only inside the enabled punch range and stops at its out point), count-in, channels (Mono downmixes the input), input gain and input latency (the finished take is shifted earlier by that amount so a late input lines up with the grid). While a take runs, the input is monitored through the armed track's own channel strip, so its fader, pan, mute and solo all apply. Finishing a take decodes it, cuts the performance window off the pre-roll, downmixes it if asked and uploads it as a 16-bit WAV; one edit then puts both the new audio node on the canvas beside the project node and the clip on the armed track, where the take replaces whatever covered its range (overlapped clips are trimmed to the take's edges and the covered middle is dropped) — so repeated passes become takes, one recording is one undo step, and no audio bytes ever enter the document. The metronome is now audible: one click per beat with the bar accent, at the volume in the project settings, following tempo and meter while they change, playing during playback and recording but deliberately kept out of the offline mixdown so an export never contains the click. Export is hardened too: Save as audio node disables itself and reads Exporting… until the render and upload finish, and the Track menu adds Export stems, which renders one stem per track offline through the same shared graph builder — a clip, instrument or MIDI track renders its own material, a group renders exactly what routes into it — and adds one audio node per stem in a single patch. Not implemented on purpose: cycle recording (one take per lap), stems for return tracks (their wet signal cannot be isolated from the senders' dry path), and stems for the master (that is the mixdown).
- Dragging an audio node onto an Audio project node on the canvas imports it into that project: the Audio project card highlights as the drop target, each dropped node gets its own new track named after the node (falling back to the studio's `Track N` pattern) with a clip that references the node, the clip starts at the studio's next-clip position and uses the studio's own duration probe (a node without a readable duration falls back to 5 seconds), the dragged node animates back to the position it started from and stays a normal draggable canvas node, and the whole multi-node drop is one undo step.
- Audio studio follow-ups: a track row is 68px and fits its header exactly, so the header column and the lane rows line up row for row with nothing overlapping (the Add track row and the master row included) and lanes always draw their clips, MIDI regions and waveforms. The header's second row uses fixed slots, so Mute, Solo, the record-arm indicator and the gain field sit on the same x on every row type (audio, instrument, MIDI, group, return, master and gain-automated rows alike): a row without the arm indicator or the automation link reserves that space instead of shifting its neighbours, and on compact widths the M / S / indicator slots shrink so the row never overflows its 200px (or 88px) header. The fader now runs -60 dB … +6 dB — the bottom of the scale stands for silence and 0.0 dB is unity — so a track, a send or the master can be boosted as well as cut; the header, the inspector, the mixer and gain automation lanes all use that one range, and a positive setting reads as `+3.0 dB`. Dragging a clip (move / trim / fade / loop), a MIDI region, an automation point or a marquee previews on the dragged element itself and writes the document once on release, so a drag no longer re-renders the studio every frame while still being one undo step. An unnamed group, return or master row reads as its role (`Master`) instead of being numbered as a track, so a fresh project no longer shows `Master Track 2`. The transport row and the options row now share one 28px control height: the tempo field, the meter select, the cycle / metronome buttons, the options-row menus and the Window button, the Grid / Snap / Auto crossfade toggles and the snap / fade-shape selects all match in height, radius, border colour and horizontal padding, and the meter select keeps its arrow inside the box instead of stacking it under its content (which used to make that select 36px tall, taller than the tempo field beside it). Both rows keep their 44px and 36px heights, and the options row's controls shrink and wrap instead of being clipped when a selected clip's own controls (fade shape, clip gain, loop, reverse) and a narrow window do not fit on one line.
- Gain is no longer a slider anywhere in the studio except the mixer's own channel-strip fader: the track header, the inspector, a send, the clip gain, the recording input gain, the metronome volume and the project master each show a compact numeric field instead. It reads the same way the slider did (`0.0 dB`, `+3.0 dB`, `-∞ dB` at silence), keeps whatever you type — `-`, `+` and `.` included — until you press Enter or leave the field, then clamps to the same range and writes the document once (double-click resets it to the parameter's default). The ruler and the playhead are draggable to scrub: press anywhere on the ruler's full height (the playhead included) and drag sideways to move the play time continuously — while playing it keeps playing and follows the pointer, the position is written straight to the transport clock and the playhead element so no frame re-renders the studio or touches the document, and a plain click still seeks in one step. The ruler shows an east-west resize cursor, a hover tint and a hint tooltip.
- The bottom toolbar is centered in the canvas area and scrolls horizontally on narrow widths. Left to right it contains Export canvas; Select/Pan toggle; Undo; Redo; an input/output menu (Assets, Recording, Audio project); a prompt menu (Prompt, Music Prompt, Speech Prompt, Video Prompt); a modifiers menu (Image Modifier); a generator menu (Image Generation, Music Generation, Speech Generation, Video Generation); a divider; Smart Canvas; a conditional Extensions menu; a Zoom popover; a Node list button; and Delete when nodes are selected. The Video media node is not offered here. Button tips are hidden while one of these panels is open.
- The Zoom tool's popover offers a 5%-500% slider with a live percentage, Reset view, the minimap toggle (highlighted while open) and a Shortcuts entry; it closes on click-away or Escape and stays open while dragging the slider.
- Coordinate rulers render below the top bar as an L (top and left), track pan and zoom, widen their tick spacing when zoomed out, and are display-only so they never capture clicks or drags; each canvas remembers its own zoom and pan across switching and reloads.
- The prompt library system is removed: no `/prompts` page or top-nav entry, no Settings → Prompt sources tab, no pick-from-library entry in canvas prompt panels, and no `prompts_search` MCP tool (30 canvas tools remain). Prompt nodes keep their editing panel, preset tag buttons and reference chips.

Speech generation uses 412x312, music generation 412x244 and the image-modifier node 460x644, all proportional.

The Video media node is no longer in the toolbar and is only created by dragging a file out of an Assets node or by a generation.

## Writing studio (文本创作器)

- The top navigation has a fourth tab, Writing Studio, at `/write`. `/write` lists every work as a card (title, template, word and unit counts) with New work (name plus a Novel / Screenplay template), rename and delete; opening a work goes to `/write/:id`, and a work is one self-contained document (outline + prose + its own codex + snapshots) stored under `infinite-canvas:writing_store` through localforage like the canvas library.
- Novel works use 卷 / 章 / 场景 / 节拍 with the chapter as the writing unit; Screenplay works use 幕 / 场 / 镜头 with the scene as the writing unit. The template is fixed at creation. Prose is stored per writing unit, so word counts, snapshots and AI context are bounded by the unit.
- The studio is a dockable layout: Outline and Codex on the left, Inspector on the right, Board and History at the bottom, the editor in the centre. The Window menu shows or hides panels and resets the layout, panel tabs drag between the left, right and bottom docks, and the layout persists per studio (same storage key prefix as the image and audio studios).
- Outline (章节管理器): collapse/expand, inline rename on double-clicking a title, per-row add child / add sibling / AI expand / delete, drag-and-drop that reorders and re-parents (drop on a row's edge to place before/after, on its middle to nest) and refuses dropping a node into its own subtree, a search box that filters by title or summary while keeping ancestors visible, and a footer with word and unit counts.
- Editor: a TipTap block editor bound to the writing unit of the current selection, with ~600ms debounced autosave, a toolbar (bold / italic / strike / H2 / bullet and numbered lists / blockquote / divider / undo / redo), a `/` slash menu on an empty line (heading, list, quote, divider, insert codex entry, AI writing), a snapshot button, and a focus mode that hides the chrome and centres the column.
- AI writing: a non-empty selection shows a floating bar with Continue, Rewrite, Expand, Condense, Polish and Dialogue (rewrite replaces the selection; the others insert at the cursor), the header has the same list for the whole unit, output streams into a preview panel with Stop / Accept / Discard, and an unconfigured text model reports "configure the text model in Settings" instead of failing silently. Prompt context is assembled from the work's logline and synopsis, the ancestor outline nodes, the codex entries linked to the node, the previous units' prose tails, the unit's own prose, and the work's POV / tense / style sheet.
- AI expand on an outline node asks the model for 3-6 children of the next level (volume→chapter→scene→beat, act→scene→shot) and creates them with their summaries; an unparseable reply creates nothing and reports a failure.
- Codex (资源库): character / location / lore / item / thread entries scoped to the work, with a kind filter, search, add, inline editing of name / aliases / summary / tags / custom key-value fields, and delete that also unlinks the entry from every outline node.
- Inspector: kind, editable title, status (Idea / Draft / Revised / Done), summary, linked characters / location / plot threads (one select per codex kind plus removable chips), tags, the owning unit's word count and revision count, and an AI expand button for nodes that have a child level.
- Board (场景看板): the work's writing units in four status columns with counts; dragging a card to another column changes its status, dropping it onto another card reorders it next to that card, and clicking a card selects it.
- History (版本历史): the live document plus the unit's snapshots newest-first, with Take snapshot, Restore (confirmed) and Delete; the live card shows the current word count and snapshots show their label, time and word count.
- Export Fountain in the studio header downloads the work as a `.fountain` file: screenplay projects emit slug lines and promote `名字：台词` paragraphs to dialogue, novel projects emit section headings with action paragraphs, and an empty work still produces a valid title page.
- The canvas writing node family is gone: no Writing menu in the bottom toolbar, no story node type or `metadata.story` field, no story relations (Story flow / Character arc / Setting / Theme / Plot thread) and no `expand_story` agent operation or permission; the connection label fallback never shows a raw key for a relation that no longer exists.

- Creating a node, duplicating/pasting nodes, and single-clicking a node no longer open the lower panel on their own; the panel only opens from the node-list panel toggle or when a plugin asks for it.

## Providers and models

- Settings has a Providers tab: several providers can be added, each with its own name, Base URL and API key (OpenRouter / OpenAI / Groq / DeepSeek / Gemini / Moonshot / Zhipu GLM / SiliconFlow / Cohere / Ollama presets fill name and URL), the last remaining provider cannot be deleted, and a provider's model list can be fetched from its `/models` endpoint.
- Each provider is a collapsible row showing its name and model count; expanding it reveals the preset, name, Base URL and API key fields. Deleting a provider takes two clicks (the first arms a confirm label, the second deletes; clicking away cancels).
- Settings has a Models tab that groups every provider's models under Text / Image / Audio / Speech / Video, lets a model's category be changed inline, lets models be added (provider + model id) or removed, and sets the default model per category through the model picker.
- Model dropdowns render as `provider/model` and list only models whose category matches what is being generated (speech nodes show Speech models, music/audio nodes show Audio models, and so on).
- A generation request goes to the chosen model's own provider Base URL with that provider's API key; an unconfigured provider falls back to the legacy global key.

## Generation

- Firing many generations routes every request through one shared queue with a concurrency limit of 2, so queued images stay visible as waiting instead of all hitting the provider at once.
- A failed generation retries up to 3 times with a 2-second backoff before it is reported as failed.
- Generated images, video, audio and text results are placed on the canvas without a connection back to the generating node; only connections the user creates are kept.
- When a generating image turns into a success it plays one subtle scale + rise + fade entrance (about 0.42s); images already on the canvas do not play it again, and the system reduced-motion setting disables it.
- After a generation completes, the image node's info strip shows the real cost read from the OpenRouter response (`usage.cost`) and marks it as real; when the response has no cost it shows a locally estimated value marked as estimated.
- A video-generation node (or a config node in video mode) set to `minimax/hailuo-3-max` (480p/768p, no audio, default) or `minimax/hailuo-3` (2K, native audio) uses OpenRouter's native async video API: the submitted body carries model, prompt, duration, resolution and aspect_ratio plus `frame_images` in first/last-frame mode or `input_references` in reference mode, the two are never sent together, the mode and slot bindings come from the connected video prompt node, every frame entry keeps its explicit `frame_type` so a lone last frame is not sent as a first frame, reference entries use the matching `image_url` / `video_url` / `audio_url` payload key, and `generate_audio` is sent only when the model supports audio; the generation node shows model, the model's own resolutions (a single full-width 2K pill when there is only one), 5-15 seconds, the six ratios (1:1 / 3:4 / 4:3 / 16:9 / 9:16 / 21:9) and the audio toggle inline without W/H fields or a settings popover, no `size` / `watermark` / `seed` field is sent, local video and audio references are read from browser storage into base64 data URLs, and a reference above 50MB (video) / 15MB (audio) or above 64MB encoded in total fails with a clear message; other video models (channel models and plugin scripts) keep the previous panel and request path.
- A video model that accepts a single keyframe (both `minimax/hailuo-3` and `minimax/hailuo-3-max`) shows one Keyframe slot in the video prompt node with a First frame / Last frame toggle that re-tags the bound image instead of ever keeping both frames, plus a hint that the model accepts a single keyframe; the submitted request is trimmed to the model's keyframe limit, so a canvas saved with both frames no longer fails. Models whose capability allows two frames keep the two-slot layout.

## Smart Canvas

- A Smart Canvas board is a fixed-ratio composite canvas with a selectable 1K/2K/4K resolution (default 16:9 / 2K) and a background colour (Transparent / White / Black / Custom) plus background opacity; changing the ratio resizes the board.
- The board is a self-contained layer document: its layers (image / text) keep position, size, rotation, opacity, blend mode and visibility inside the board node's own `boardLayers`, in board-local coordinates (array order is z-order, index 0 at the bottom), so layers no longer depend on canvas node positions or `metadata.boardId`.
- Dropping image or board nodes on a board appends one image layer per dropped node (fitted to the board centre at the source aspect ratio, named after the node) and then animates every dropped node back to where its drag started; nodes stay ordinary draggable canvas nodes instead of sitting on the board, and the board highlights as the drop target while dragging.
- The board node on the canvas is an info-only card (the same structure as the audio project card): the board icon, a ratio · resolution line and the layer count, with the node's title label above the card as before. It no longer renders the board's background, grid, image layers, text layers or nested boards, so editing the document no longer re-renders the canvas card; the layer document renders in the Image Studio and on composite / export only.
- The board panel is reduced to the board settings (ratio / resolution / background / opacity) and Save as image node; double-clicking opens the composite preview and the hover-toolbar Save as image node composites on demand (recursing into nested boards and drawing layers in order with their blend mode, opacity and rotation) and adds an image node to the right.
- Layer order, visibility, blend mode, opacity and rotation drive both the preview and the export: the preview uses CSS `mix-blend-mode` / `rotate` and the export uses canvas `globalCompositeOperation` with centre rotation; text layers draw their multi-line text with the layer font size and colour.
- Dragging a board onto another board makes it an image layer of that board (nested boards render recursively and stay clipped to their own rectangles), a board can never be dropped into itself or a descendant, and a stored cycle is skipped during preview and compose instead of looping.
- The Image Studio workspace is a Photoshop-style layer editor over the active board's own layer document: a board bar (board switcher, ratio / resolution / background / opacity settings, zoom readout, Fit, Save as image node) with a tool options bar under it that starts with the Select / Image / View menus and then shows the active tool's own options (brush / eraser size, hardness and opacity, the bucket and wand tolerance, the selection feather and anti-alias, the gradient type, blend mode, opacity, stop position, reverse and colour pair, the shape type, fill, stroke and stroke width, and the foreground colour swatch), a left tool strip (Move, Hand, rectangular and elliptical marquee, lasso, polygonal lasso, magic wand, quick selection, brush, eraser, paint bucket, gradient, shape, eyedropper, zoom in / out), the document viewport in the centre and dockable panels around it (Properties / Adjustments on the left, Layers / Channels / Paths / History / Actions on the right and the asset panels at the bottom), with every panel listed in the options row's Window menu, moved between docks by dragging its tab, resized by dragging a splitter and the layout remembered per workspace.
- The viewport pans by dragging empty space or holding Space, zooms at the cursor with the wheel (5%-800%) and fits the document to the window; the document renders its background, layers and groups through the same frames, blend modes, opacity and rotation as the board preview and clips to its own bounds. The selected layer gets a Photoshop bounding box with four corner scale handles and a rotation handle (Shift snaps to 15 degrees), dragging the layer body moves it, locked layers cannot be transformed, hidden layers are not rendered, and a text layer is edited inline by double-clicking it on the document. The View menu toggles rulers (top and left, with tick labels that follow pan and zoom, and dragging from a ruler creates a horizontal or vertical guide — guides are remembered per board for the session), a document grid over the viewport, the guides themselves and snapping: while a layer is moved or resized its edges and centre snap to guides, the document edges and centre and the other layers' edges and centres (within 6 screen pixels, shown as a coloured line, with an indicator while snapping is on); a guide can be dragged again or dropped outside the document to remove it, and Clear guides removes them all.
- The layer document has a pixel layer kind: dragging the brush or the eraser across the document paints continuously into the selected pixel layer (size, hardness and opacity come from the options bar, and a brush ring follows the cursor and scales with zoom), the eraser erases with destination-out and only its own layer, the paint bucket fills 4-connected pixels by tolerance, and the eyedropper picks the colour under the cursor out of the composite and makes it the foreground colour. When the active layer is not a pixel layer (nothing, or a text / image / group layer is selected) the first paint automatically creates a pixel layer covering the whole board and selects it, and the options bar says so. One drag (or one bucket click) writes `boardLayers` exactly once, on release, so a single undo restores the whole stroke; layers keep their own position, rotation, opacity and blend mode, and the board preview and the Save as image node export agree. A pixel layer's bitmap is stored through the image store behind its own `storageKey` (never baked into the node metadata), so the saved project stays small and the image cleanup sweep keeps the bitmap alive.
- Selections are a document-sized mask canvas (alpha = selected) that lives in editor state only and is never written into the board document: the rectangular and elliptical marquee, the freehand lasso, the polygonal lasso (click to add points, close on the start point or press Enter, Esc cancels), the magic wand (tolerance, contiguous, sample all layers or the active pixel / image layer) and quick selection (drag on the composite to grow along similar colours, Alt-drag to shrink) all create one, with Shift adding to and Alt subtracting from the current selection. The selection boundary is drawn as animated marching ants (hidden while a gesture is in progress), the Select menu offers Select all / Deselect / Inverse / Feather (Ctrl+A, Ctrl+D, Ctrl+Shift+I), the selection survives tool switches, and it is cleared by Deselect and whenever the document changes (board switch, ratio change, image size, canvas size, rotation, crop or trim). Every paint op — brush, eraser, paint bucket and gradient — is clipped to the selection, and a new shape created under a selection gets a layer mask generated from it.
- A layer can carry an optional mask (`maskStorageKey`, another `image:`-prefixed bitmap in the image store where white shows and black hides): the Layers panel shows a mask thumbnail next to the layer thumbnail and highlights which of the two is being edited, Alt-clicking the mask thumbnail views the mask itself in the document, and the Properties panel offers Add mask (from the current selection, or a full-white mask), Delete mask and Apply mask (baked into the bitmap; enabled for pixel layers only). With the mask as the edit target the brush, eraser, bucket and gradient paint the mask instead of the bitmap — a dark foreground colour hides, a light one reveals, and the eraser restores — while the preview uses a CSS `mask-image` and the composite uses a canvas `destination-in`, both multiplying the layer's own content by the mask before the layer's opacity and blend mode apply.
- The gradient tool paints linear or radial gradients with two colour stops plus a stop position, a blend mode, an opacity and a reverse toggle into the active pixel layer or mask, clipped to the selection; the shape tool drags out a rectangle, rounded rectangle, ellipse, polygon or line (Shift constrains the proportions, and the corner radius / side count are edited in the Properties panel) as a new `shape` layer kind that can then be moved, scaled and rotated like any other layer, with fill, stroke and stroke width editable in the options bar and the Properties panel; the preview draws the shape as an inline SVG and the export draws the same path data through `Path2D`.
- The Image menu provides Image size (resamples the whole document: every layer's geometry and every pixel / mask bitmap is scaled), Canvas size (changes the document box without scaling the content, with a nine-way anchor), Image rotation (90° clockwise / counter-clockwise, 180° and an arbitrary angle that grows the canvas to the rotated bounding box), Crop to selection and Trim border (removes the empty border around the visible layers). Every operation writes through `boardLayers`, resizes the board node on the canvas with the document and updates `boardRatio` to the nearest preset ratio.
- The Layers panel lists layers topmost-first with a thumbnail (the resolved image bitmap, a pixel layer's own bitmap, a mask thumbnail beside it when the layer has one with the current edit target ringed, a T glyph for text, a folder glyph for a group, a shape glyph for a shape layer), an eye and a lock toggle per row and an inline rename on double-click; the header row carries add image layer (a picker of the canvas's image nodes), add text layer, group, ungroup, duplicate, delete, move up and move down, plus the selected layer's blend mode and opacity. Rows reorder by drag (dropping onto a group puts the layer inside it) as well as by up / down.
- Tool shortcuts are V for Move, H for Hand (Space still switches to Hand temporarily), M / Shift+M for the rectangular and elliptical marquee, L / Shift+L for the lasso and polygonal lasso, W for the magic wand, A for quick selection, B for the brush, E for the eraser, G for the paint bucket, Shift+G for the gradient, U for the shape and I for the eyedropper (Ctrl+A / Ctrl+D / Ctrl+Shift+I select all, deselect and invert), and [ / ] step the brush size.
- A group is a single-level container with its own name, opacity, blend mode, visibility and lock whose children composite in isolation before the group's own opacity and blend mode apply, in both the board preview and the exported PNG.
- The Properties panel edits the selected layer's name, position, size, rotation (image and text layers), opacity and blend mode, a mask row (add / delete / apply), the shape parameters (shape kind, fill, stroke, stroke width, corner radius, side count) for shape layers and the text content, font size and colour for text layers. Every edit writes the board node's own `boardLayers` through the canvas state, so undo / redo, autosave, reload persistence and Save as image node keep working.
- Adjustment layers are a new `adjustment` layer kind (array order is still z-order) offering 15 non-destructive adjustments: Brightness/Contrast, Levels, Curves (a draggable-point curve editor), Exposure, Vibrance, Hue/Saturation, Color Balance, Black & White, Photo Filter, Channel Mixer, Gradient Map (add and remove colour stops), Invert, Posterize, Threshold and Selective Color. An adjustment layer affects only the layers below it in the same container — the document level or its own group — with Photoshop semantics, and carries its own opacity, blend mode, visibility, name and mask; parameters run per pixel through `ImageData` (a 256-entry lookup table wherever one applies). Both the Adjustments panel under the Layers panel and the Layers panel footer's Adjustment layer menu create one, and clicking a type while an adjustment layer is selected replaces its type and resets that type's defaults. Adjustment layers have no pixels of their own, so they are ignored by the trim bounding box and never block clicking another layer on the document, and the Properties panel shows the matching parameter controls for the selected adjustment.
- The Filter menu lists 22 destructive filters grouped by kind — blur (Gaussian Blur, Box Blur, Motion Blur, Radial Blur, Tilt-Shift, Iris Blur), sharpen (Sharpen, Unsharp Mask), noise (Add Noise, Despeckle, Dust & Scratches), pixelate (Pixelate, Crystallize), stylize (Emboss, Find Edges, Solarize, Clouds, Lens Flare) and distort (Ripple, Pinch, Spherize, Liquify). Every filter has its own parameter dialog with a live preview computed on a downscaled copy; applying rewrites the target layer's bitmap (text, shape, image and group layers are rasterised into a pixel layer first, and the dialog says so), writes `boardLayers` exactly once so a single undo restores the layer, and clips the result to the layer mask and the current selection so uncovered pixels keep their original values. Repeat last filter re-applies the previous filter with its previous parameters; Liquify is interactive instead (drag on the preview to push pixels forward, Reset starts over, with brush size and pressure parameters) and is not remembered as the last filter.
- Layer styles (fx) live on every non-adjustment layer as stroke, drop shadow, inner shadow, outer glow, inner glow, bevel & emboss, satin, colour overlay, gradient overlay and pattern overlay, each with Photoshop's main parameters (size, position, colour, angle, distance, spread, depth, soften, highlight / shadow colour and opacity, scale, opacity and blend mode; the gradient overlay edits its own stops and the pattern overlay uses built-in checker / dots / stripes / crosshatch patterns). Drop shadow and outer glow draw under the layer's own content and the remaining styles draw over it, matching Photoshop. The Layers panel footer has a Layer style entry and double-clicking any layer row opens the same panel, where each style has an enable checkbox and its parameter editors.
- Preview and export now share one raster renderer: `renderPsDocument` (board document to canvas) is used by the Save as image node export, node generation, the eyedropper / magic-wand sampling and the compositor's document surface, so adjustment layers and layer styles have exactly one implementation and preview and export agree by construction. Documents without adjustment layers or enabled styles keep the existing DOM rendering path unchanged (same live painting, blend modes and masks); as soon as one appears the editor switches to the raster path, keyed by a content signature so an unchanged document is not redrawn.
- The compositor's panels are dockable. Every panel (Layers, Channels, Paths, History, Actions, Adjustments, Properties and the asset panels) is declared once and shown, hidden or moved from the options row's Window menu; dragging a panel's tab docks it to the left, right or bottom edge (several panels stack as tabs in one dock), dragging a splitter resizes that dock and the layout is stored per workspace, so the old fixed right column is gone. The asset panels are: a real Photoshop-style colour picker (saturation / brightness square, hue strip, HSB, RGB and hex fields, foreground / background swatches with swap and reset to black and white) that is the editor's colour source, a swatch grid where the current foreground can be added and any swatch removed by right-click, a gradients panel whose bar edits stops by drag with a colour, position and midpoint per stop plus name / save / delete, a patterns panel that defines a pattern from the current selection or from the selected layer, and a brushes panel where every preset shows a live preview stroke drawn through the same dab as the brush tool and its size, hardness, opacity, spacing, scatter, angle, roundness, dynamics and texture settings are edited, saved, renamed and deleted. Presets are user data, so they are persisted with the localforage-backed `use-ps-asset-store` (never localStorage); a pattern's bitmap goes into the image store behind an `image:` key, and the shared image cleanup is given the pattern list so saving a preset can never have its bitmap swept away.
- Free transform gained skew, distort, perspective and warp: entering a mode from the new Edit menu's Transform entries (or Ctrl+T for the plain bounding box) replaces the layer frame handles with the mode's own handles — eight edge / corner handles for skew, four corners for distort, mirrored opposite corners for perspective and a draggable 4×4 control mesh for warp. The layer stores the transform as a normalized quad or 4×4 mesh (`transform` on the layer), so move, scale, rotate, groups and masking keep working, and the shared raster renderer draws it by subdividing the mesh into affine triangles (an affine mesh draws as a single clipped transform). Preview and export therefore match by construction. The Edit menu also has Numeric transform… (move X / Y, scale X / Y, rotation, skew X / Y), Repeat last transform (Ctrl+Shift+T) and Clear transform, every transform is one undo step, and shapes and text accept exactly the same transforms.
- The text layer gained the fields behind a Character and a Paragraph panel, shown under Properties whenever a text layer is selected: font family, size, colour, faux bold / italic, underline and strikethrough toggles, tracking, kerning, leading, baseline shift, horizontal and vertical scale and normal / upper / lower / small-caps, plus align (left, centre, right, justify), left / right / first-line indent, space before and after and a hyphenation toggle. All of it is laid out and drawn by the shared raster renderer (glyph by glyph, so tracking, kerning, scaling and the decorations agree with the export), including text on a path — a text layer can follow any saved path and its glyphs are placed and rotated along the path by arc length — and Warp Text (arc, arc lower, arc upper, flag, wave, fish, rise, bulge, shell, squeeze) with bend and horizontal / vertical distortion, rendered through the same mesh path as the layer transform.
- The Channels panel shows the RGB composite plus the red, green and blue channels of the document: clicking a channel shows that channel as greyscale in the viewport (the composite still comes from the shared renderer, then the shown channel is copied into all three), and every channel has an eye that removes it from the composite in both preview and export. A selection can be saved as a named alpha channel, loaded back as a selection, renamed in place and deleted; alpha channels are document data in the board's own metadata with `image:`-keyed bitmaps, so they save, reload and export with the board.
- The Paths panel adds vector paths to the board document: the pen tool places anchors on click and drags symmetric handles for curves, closes by clicking the first anchor and ends with Esc, the direct selection tool moves anchors and their two handles, and the panel lists every path with an SVG thumbnail, an eye, an inline rename, new / duplicate / delete, Make selection, Fill path and Stroke path (with a colour swatch). Paths live in the board's metadata; their geometry is shared with the renderer through one flattened-polyline helper, so a text layer following a path and a path filled into a layer use the same shape.
- The History panel is a clickable list of the document's states: every `boardLayers` commit pushes an entry whose name comes from the operation, clicking an entry restores that state, the arrows step backward and forward, Snapshot pins a copy of the current state, and the list is capped at 50 states (the header says so). History is editor state only — it lives in memory for the session, is never written into the board or the project file, and the panel states that in the UI.
- The Actions panel records the editor's own document commands: Record starts a capture, the recorder stores menu commands (select operations, crop, trim, the three rotations), layer commands (duplicate, delete, move up / down, group, ungroup, rasterize), added adjustment layers, applied filters with their parameters, and numeric transforms; Stop ends the capture and the step list can be named and saved, played back on demand, renamed and deleted. Freehand brush strokes are deliberately not recordable and the panel says so. Actions are user data, persisted with the same localforage-backed store as the presets.
- The tool strip gained the pen and the direct selection tools (P / Shift+P), the Select / Edit / Image / Filter / View menus are joined by Edit for free transform, numeric transform, repeat transform and clear transform, and the options bar follows the tool: the pen and direct selection show the active path and let the active pattern be cleared, the bucket shows the same, and entering a transform mode shows the mode switcher and a Done button.

## Image tools

- An image node's hover toolbar shows the enabled quick tools, which by default are info, delete, download, mask edit, crop, remove background, split, resolution, analyze, extract text, segment and duplicate; the "Show labels" toggle adds the button text labels for every node type and persists.
- Remove background runs the ~42MB background-removal model in a Web Worker and adds a transparent-PNG node to the right, connected and selected; the model is downloaded from Settings → Local models or on first use with progress, and the interface stays responsive.
- Split opens a point-prompt dialog (left-click foreground, Alt or right-click background, with undo-last and clear) that runs MobileSAM locally (ONNX, roughly 45MB downloaded on first use and cached), reports the chosen mask's IoU with an overlay and creates a transparent-background node to the right; the encoder runs once per image so later points stay responsive.
- Resolution has three tabs: Algorithm upscale (1K/2K/4K presets, algorithm choice, output preview, confirm disabled when the source long edge already reaches the target), Algorithm downscale (1024/768/512 presets plus a 64-4096px target, enabled only when the target is smaller than the source) and AI enhance (2x/4x factor and an editable prompt, calling the configured image model with the node image as the only reference). Local results connect as upscale results and AI results as enhance results, and the new node is selected.
- Analyze opens a dialog with the image's dominant-colour palette, its EXIF key/value list (or an empty note) and its perceptual hash; choosing a ratio (1:1 / 4:3 / 3:4 / 16:9 / 9:16) and confirming adds a content-aware cropped image node to the right.
- Extract text sends the image to the configured text model and creates a selected text node to the right; with no text model or key it opens Settings instead, an empty result shows an error and creates no node, and a failed request surfaces the error without a stuck loading toast.
- Double-clicking an image opens the large preview, which has a download button at its bottom; the hover toolbar also offers download.
- Mask edit requires a painted area and an edit request; confirming writes a "mask annotation" image node below the source (the original with a translucent blue painted overlay) and a result node to the right connected to both, and sends them as two ordinary reference images without the `mask` API parameter. The brush ring tracks the pointer and painting stays smooth while zooming.

## Assets node and local folders

- The toolbar and create menu offer a single Assets node with one folder binding: the bound folder is the root of a folder browser, its subfolders are listed above the files with a folder icon (files stay a plain name-only vertical list, no thumbnails or grid, capped at 200 files with a status note), dragging a file row onto the canvas creates the matching node, clicking a row inserts one at the centre, and the binding and file list are restored on reload and canvas switching.
- Inside the Assets node, a compact navigation row sits under the header: a back button plus a breadcrumb of the root folder name and each path segment. Clicking a folder row enters it, clicking a breadcrumb segment jumps back to that ancestor, and the back button goes up one level and is disabled at the root, so navigation can never leave the bound folder. The current path lives in memory only and is not persisted — reloading or switching canvases returns the node to the root.
- Each Assets node binds and remembers its own folder independently (stored per node in IndexedDB, never in the node metadata or the saved project); a newly created Assets node starts unbound with an empty list, so it never inherits another node's folder.
- Dragging an image node onto the Assets node bounces it back to its original position, writes the image into that node's bound folder, shows saving → success/failure and refreshes the file list; the node highlights as a drop target while dragging. The separate output folder and automatic upstream writes are gone.
- The Assets node has a source dropdown at the top-left (Local folder / Extension cache) instead of repeating the node name; the choice is stored on the node metadata, survives a reload and canvas switching, and each source keeps its own header actions and list.
- With the OpenCanvas browser extension installed and connected, Extension cache mode lists the cached image file names (same 200-item cap and count as the folder list), and each row can be dragged onto the canvas or clicked to insert a normal image node; with no extension the node shows an "Extension not detected" hint with install guidance and no errors, and local-folder behaviour is unchanged.
- Hovering a file row in the Assets node reveals a preview button: clicking it opens an overlay showing that resource — image, video player, audio player, or text content — while the row itself still inserts on click and drags onto the canvas as before. The list stays name-only: nothing is read or preloaded until you preview a specific row, and closing the overlay releases the preview.

## Canvas MCP and agent permissions

- The canvas browser bridge and HTTP MCP endpoint now run as a standalone local Python service (default `http://127.0.0.1:3210`, protocol version 7, 29 agent tools) instead of inside the web app: the frontend no longer mounts the service from Vite, `web/server` is gone, and an MCP client at `http://127.0.0.1:3210/mcp` (plus `/health`, `/config`, `/events` and `/canvas/state|activate|result`) sees the same tools. The canvas connects to a configurable base URL with an optional bearer token instead of the page origin, and the e2e smoke test checks that bridge health tolerantly (it only warns when the local server is not running).
- Settings → Agent starts with a "Local Agent connection" section: it sets the bridge base URL (default `http://127.0.0.1:3210`) and the bearer token, stores both in the browser (`canvas-agent-url` / `canvas-agent-token`, so no rebuild is needed) and reconnects on save while showing the current connection state. The URL must be the literal `127.0.0.1` (Chrome and Firefox allow HTTPS→`http://127.0.0.1`, Safari blocks it, and Chrome shows a Local Network Access prompt). The token travels as `Authorization: Bearer` on HTTP requests and as `?token=` on the SSE stream, since `EventSource` cannot set headers.
- `canvas_create_node`, `app_apply_ops`' `add_node` and `delete_node` accept every built-in type (text, prompt, music prompt, speech prompt, video prompt, image, video, audio, config, image generation, speech generation, music generation, video generation, smart canvas, assets, recording, image modifier); an unknown type is rejected, and `canvas_group_nodes` / `canvas_ungroup_nodes` do not exist.
- Node tools: an MCP client can set lock/hide (`canvas_set_node_flags`), bulk rename (`canvas_bulk_rename`, an exact title for one node or numbered `Title 1`, `Title 2`, … for several), align/distribute (`canvas_align_nodes`; distribute needs 3+ nodes) and duplicate (`canvas_duplicate_node`, default 40/40 offset, selecting the copy). Unknown ids are ignored instead of breaking the canvas.
- Settings → Agent lists one toggle per operation type (10 types, all allowed by default); turning one off blocks that operation, shows a warning and counts it as blocked.
- Every agent operation batch appears in the Agent audit log with its time, operation count, blocked count and a short summary; the log keeps the newest 100 entries, Clear empties it and Restore defaults re-enables every permission. Replaying an entry re-applies the same operations and adds a new entry marked as replayed.
